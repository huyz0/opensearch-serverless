# 0087: IVF and PQ k-NN search serve model-mapped fields from lucene-rust's IVF files, with the model's centroids and codebooks shared per node

**Status:** Accepted after independent review, 2026-11-28 (accept with changes; three blocking and seven other findings, all folded in). Design only: no code, no setting and no route exists. Each slice in "Slices" needs its own spec. Settles stage 3 of [ADR 0086](0086-knn-engines-and-models-are-native.md) and amends its training bound (decision 5 here).

## Context

[ADR 0086](0086-knn-engines-and-models-are-native.md) left one question open: a mapping that names `model_id` (or `method: ivf`) is refused until there is a decision on the segment format and the memory model. This ADR makes it.

What the stock plugin 3.10.0 does, from the recordings in `fixtures/stock-plugins/knn-train.json` (#996):

- `_train` builds a Faiss IVF template (`ivf`, encoder `flat` or `pq`; `sq` is not recorded) from a training index and stores it as a model: `model_definition` `{name, parameters{nlist, nprobes, encoder{name, parameters}}}`, `compression_level` `1x` (flat) or `4x` (pq), `state` `created`, `failed` (too few vectors: Faiss's `nx >= k` check, with `max_training_vector_count` cutting the sample) or `training`. PQ's `m` must divide the dimension; `code_size` is 8.
- A field `{"type":"knn_vector","model_id":"m1"}` has no dimension, space or method in the mapping, and `GET _mapping` echoes exactly that. An index naming a **model that does not exist is created** (200); nothing is checked until a document is written.
- A `knn` query on such a field takes `method_parameters.nprobes`; `ef_search` is refused 400 `Parameters not valid for [FAISS]:[ivf]:[k] combination: [Validation Failed: 1: Unknown parameter 'ef_search' found;]`. The default `nprobes` is the model's (`1` when the request gave none).
- Deleting a model that an index names is 409 `delete_model_exception` listing the indices.

What lucene-rust holds at the pinned rev `dbb34e98`:

- **`lucene-ivf`** (`KnnVectorsFormat::Ivf`, files `.ivm .ivp .ivv`): `.ivm` (per field: centroids, cluster sizes, radii, the quantizer's name and state) is read whole at open; `.ivp` holds one contiguous block of codes per cluster, read by one range per probed cluster; `.ivv` holds full vectors in cluster order, read per reranked candidate. Quantizers `bbq`, `osq2/4/7`, `erq2-8`, `rabitq`, `auto`; `Quantizer` and `QuantizerFactory` are traits with a registry, and `IvfWriter::add_field_with_clustering` takes centroids and assignments from the caller. Its k-means chooses its own cluster count from a target cluster size; there is no fixed `nlist`.
- **`lucene-faiss`** (`.faissm/.faissd`): Faiss's own serialization, read whole into memory, for sandbox Lucene `main` with no compatibility guarantee; HNSW, IVF-flat and SQ8, a port of Faiss's `Clustering` (private), **no PQ**, not wired to `IndexWriter`.
- **`lucene-vector-quant`**: the quantizers above. **No product quantizer.**

Forces: requests scale with nodes and bytes, never with records or elapsed time per index; LIST is banned on a read path; at most three sequential round trips to rank and one to fetch rows ([principles](../principles.md)); memory is reserved before it is held ([ADR 0004](0004-bounded-memory-and-streaming.md)); a feature with a measured downside is a setting; plugins have no enable flag ([ADR 0086](0086-knn-engines-and-models-are-native.md) amendment, #997).

## Decision

1. **A model-mapped field is written in lucene-ivf's file layout, with the model's coarse centroids and quantizer taken from the model, not trained per segment.** Postings are `.ivp`, rerank vectors `.ivv`, per-cluster sizes and radii `.ivm`. The segment does not embed the centroids or the codebooks; its `.ivm` names the model (`model_id`, blob CRC, `nlist`, dimension) and the reader is handed the shared model (decision 3). The raw vectors stay in the Lucene flat-vector files beside it, as every vector field's do ([ADR 0039](0039-knn-vectors-in-the-segment.md)), so `_source` derivation, merge input and exact fallback keep working.
2. **The model blob is our own versioned, CRC-checked format**: header (version, space, dimension, `nlist`, encoder name and parameters), `nlist x dimension` centroids as `f32`, and for `pq` the codebooks (`m x 256 x (dimension / m)` `f32`). The REST `model_blob` is its base64: opaque to clients, **not Faiss's bytes** and not loadable into Faiss (deviation, stated; the recordings show clients only echo it). A blob over 1 MiB (ADR 0086's per-description cap) is its own object, `knn/models/blobs/<model_id>/<run>`, where `<run>` is the training run's identifier, written **before** the marker swap; the model document carries `blob_bytes`, `blob_crc` and `run`, so the key is derived, never discovered, and a re-created id never reuses a key. The swap to `created` is a compare-and-swap on the `training` marker of **that run**, so a trainer past `training_timeout` (read as `failed`) cannot later turn the model `created`; its blob is an orphan that no document names. A delete removes the object only after the tombstone of decision 9, so a late DELETE cannot land on a later model's blob. `GET /models/{id}` returns `model_blob` inline up to 1 MiB and the empty string above it (deviation, stated), and model search projects `model_blob` out of every hit (the recorded search excludes it). The REST create/GET path reserves the base64 transient from the request pool. Total blob bound 64 MiB (ADR 0086).
3. **The node holds each model's centroids and codebooks once, in a `knn_models` pool.** A new pool sized by `serverless.knn.models_bytes` (default 256 MiB), charged **before** the blob is read, from the `blob_bytes` the index descriptor carries (decision 8). The pool is keyed by (tenant scope, model id, run); the scope is that of the `knn/models/` set, per tenant. The pool is an entry of the node's budget split and the settings registry like every pool, and the reader does not start with it empty. The resident model includes its routing tree, charged with it (`nlist x 8` bytes of parents plus the centroids' norms, under 5% of the centroids). A pool smaller than the working set thrashes to one blob GET per search; that scales with bytes and is accepted. A flush refused by this pool retries with backoff and holds its node-log entries, as for any refused reservation, so writes are delayed, not lost. Every segment of every index mapped to the model shares one resident copy; entries are closed least recently used first when no search or writer holds them, as [ADR 0014](0014-open-indexes-pool.md) does for open indexes. A model larger than the pool is 429 `circuit_breaking_exception` with durability `PERMANENT`. The resident model also holds the centroids' routing tree, built once.
4. **Search ranks the centroids once per query, then probes the same lists in every segment.** `nprobes` lists are probed in each segment (Faiss's meaning for one merged index; `segment_nprobe` is not used). Per segment: the cluster sizes in `.ivm` are known at open, the probed clusters' `.ivp` ranges are read in one parallel round, and the best candidates are reranked from `.ivv` in a second only when rerank is on (decision 6). `encoder: flat` has no codes: the probed lists' vectors are read from `.ivv` as one contiguous range per cluster and scored exactly. The rank path is therefore **round 1: descriptor and manifest** (the descriptor names the model's key, `run`, `blob_bytes` and CRC, so the pool charge needs no model document); **round 2: the model blob in parallel with every segment's `.ivm`**; **round 3: the probed lists' postings** (`.ivp`, or `.ivv` ranges for `flat`); then the row fetch. That is three rounds cold and one warm, and a resident model adds no request. Ranges of adjacent probed clusters are coalesced into one read, and the `s3-cost` test asserts the exact round count cold and warm and a bound on the reads of a probe. **Reranking (`pq_rerank` on) adds a fourth round and is outside the three-round budget, an opt-in like `rerank: exact`: its row is added to the request budgets, and flipping its default needs the owner's decision.**
5. **Training** is ADR 0086 decision 2, completed:
   - **Sample.** The training index's vectors are streamed through ranged reads of its flat-vector files (`ceil(bytes / 8 MiB)` GETs, once per run) into a reservoir of `S = min(n, max_training_vector_count, ppc x max(nlist, 256 if pq))` vectors, where `ppc` is 256 (Faiss's points per centroid) cut to what the `training` pool allows and refused below 39, the floor under which Faiss only warns (the refusal is this ADR's choice).
   - **Bound, computed before the first read:** `S x dimension x 4` (sample; PQ residuals computed in place) `+ 2 x nlist x dimension x 4` (centroids and the k-means accumulators) `+ nlist x 8` (counts) `+ S x 4` (assignments) `+ 256 x nlist x 4` (one score block) `+ 256 x dimension x 4` for PQ (codebooks) `+` the range buffers (8 MiB times a read parallelism of 4), reserved from the `training` pool; a job that does not fit is 429 and runs nothing, and the response says how many bytes it needs. At the default 256 MiB and `dimension` 768 this serves `nlist` up to about 300 at Faiss's full 256 points a centroid and about 2,000 at the floor, before the accumulators and buffers above, which the spec's test measures; a larger `nlist` needs the setting raised, and the refusal says so.
   - **Algorithm.** Coarse k-means is Faiss's `Clustering` as `lucene-faiss` already ports it (25 iterations, spherical for inner product), exported from lucene-rust with the sample size passed in. PQ codebooks are trained **on residuals** (the vector minus its coarse centroid), `m` independent 256-centroid k-means, as `IndexIVFPQ` does by default. Fewer sample vectors than clusters (`nlist`, or 256 for PQ) fails the model with the recorded message shape (`Number of training points (n) should be at least as large as number of clusters (k)`); the stock message text carries C++ file paths and is not reproduced.
   - The recorded validations (`knn-train.json`) are the spec's acceptance list; they are unchanged by this ADR. **This replaces ADR 0086's training bound** and takes the k-means port from lucene-rust instead of writing it here; ADR 0086 carries an amendment note.
6. **PQ rerank is a setting, off by default.** Faiss answers an IVFPQ query from asymmetric-distance estimates and returns those scores. Reranking the best `k x rerank_factor` candidates from `.ivv` is more accurate and returns exact scores, but costs the third round and `.ivv` range reads. Principle 8 makes it a setting: `serverless.knn.pq_rerank` (cluster default `false`), overridable per index by `index.serverless.knn.pq_rerank`, and the PR that adds it measures recall@10 and p50/p99 with and without, on the recorded dataset and a generated one (provisional on an emulator), and flips the default only if rerank wins in most cases. Existing tests pin the behaviour with it off; new ones cover it on; both run in CI.
7. **`ivf` with a `flat` or `pq` encoder serves spaces `l2` and `innerproduct`.** `sq` is not in the recordings and is refused until one exists. `cosinesimil`, `hnsw` with a `pq` encoder (the recording shows it refused at train time: PQ `m` not dividing the dimension, and it is not otherwise recorded), radial queries (`min_score`, `max_distance`) and a `filter` on an IVF field are **refused as unsupported until a stock recording exists**, never approximated. Scores use the per-space translation the `lucene` engine path uses (checked against the `knn-train.json` search step: nearest score 1.0, then 0.667 and 0.624).
8. **A model-mapped field is resolved lazily, and writes check it.** An index naming a missing model is created, as recorded. The first flush of a model field stamps the model's key, `run`, `blob_bytes` and CRC into the index descriptor by one compare-and-swap (once per index and model), and each segment's `.ivm` names the same CRC. A document write to the field needs the model: its document (not the blob) is read through a node-local cache with a 60 second TTL, refreshed only when a write arrives (the shape of [ADR 0073](0073-stored-painless-scripts-resolve-through-a-ttl-cache.md): requests scale with nodes and models that see writes, not with elapsed time), and a write is 400 when the model is missing, not `created`, or of another dimension (this check is the ADR's own choice; the recordings stop at index create). A flush needs the blob, through the pool. A segment names its model's CRC; a search that finds another CRC fails the shard with a message saying the model changed, never reads codes under the wrong codebook.
9. **A model in use is found by a reference document, not a scan.** `knn/model-refs/<model_id>` (same scope as the models) is a document set entry listing the indices that name it, bounded at 10,000 names (an index past it is refused 400). It is written by compare-and-swap **before** the index descriptor on create and on a put-mapping that adds a `model_id` field, and removed **after** it on index delete (a crash leaves a stale reference, never a missing one). `DELETE /models/{id}` first compare-and-swaps the entry to a **tombstone**; a create or put-mapping that finds a tombstone is refused, so a delete cannot race a create. It then checks each named index still exists with one GET each, prunes stale names (a compare-and-swap write), and if live ones remain clears the tombstone and answers the recorded 409; otherwise it deletes the marker, then the blob object, then the entry. No LIST and no scan of mappings. It costs one GET per named index on a rare admin path, a stated exception to "never scales with indexes" for model delete alone. An index with no `model_id` field costs nothing more.
10. **Merges keep the model.** Merging segments of one model concatenates postings list by list; no clustering runs, and the merged segment names the same model. A merge of segments naming different CRCs is refused (it cannot happen while model ids are create-only).
11. **No new unsafe, no new dependency outside lucene-rust, no plugin-tier module.** All code is safe Rust in existing crates plus lucene-rust; ADR 0080's native tier is not used.

### What lucene-rust must add (own PRs there, each its own rev bump here, landed before the node slice)

1. **`lucene-vector-quant`: a product quantizer `pq`.** `QuantizerFactory::train` from a residual sample (`m`, 8 bits), `encode` of the residual against its cluster centroid (`uses_centroid` true), a `QueryScorer` that builds one lookup table per probed cluster (`m x 256` floats, `l2` and inner product) and sums `m` entries per code, `state` holding the codebooks, registered in `QuantizerRegistry` and appended to `IVF_QUANTIZERS` (wire number 13; `auto` stays 12). Codes are `m` bytes.
2. **`lucene-ivf`: shared-model fields.** An `.ivm` version where a field names a model instead of holding centroids and quantizer state, and keeps the per-cluster sizes and radii; `IvfWriter::add_field_with_model` (centroids and quantizer given, assignments computed by one block matrix product against the shared centroids); `IvfReader` opened with a `SharedModel` handle; a **flat** scan mode that scores a probed cluster's contiguous `.ivv` range exactly; a merge entry that concatenates by list.
3. **`lucene-faiss`: export the `Clustering` port** (`pub kmeans::train(sample, d, k, metric, points_per_centroid)`) and a `pq` trainer beside it, so training uses the algorithm Faiss does.
4. **`lucene-codecs`: a per-field format variant** for a model-mapped IVF field, `IvfModel { rerank_encoding, quantizer }`, selected with `set_knn_vectors_format_for_field`.

### What the node does

- Mapping: accept `model_id` (a mapping with `method: ivf` and no `model_id` stays refused: Faiss needs training, and a model names it), echo it as recorded, add the model reference (decision 9).
- Model store: the blob object and `blob_bytes`/`blob_crc` (decision 2), the pool (3), the lazy resolution (8). The model-store routes themselves belong to [knn-plugin-api](../specs/knn-plugin-api/SPEC.md) and are touched only for the blob object and the reference check.
- `_train` (5) under the node-local task registry ([ADR 0072](0072-tasks-are-node-local-memory-with-no-blob-requests.md)).
- Query: parse `method_parameters.nprobes` (a positive integer up to `nlist`; the recorded `ef_search` refusal), rank centroids once, hand every segment the probed lists.
- Stats: `training_requests`, `training_errors` and the `faiss_initialized` flag count what ran; the `native_engine_hnsw_requests` stat has an IVF counterpart.

## Request counts and memory (provisional until each slice's `s3-cost` test asserts them)

- **Search, warm:** 0 model requests; ranged reads of the probed lists per segment, adjacent lists coalesced, at most `nprobes x segments` before the page cache, none that scale with records. **Cold:** `+1` GET of the model blob per node per model, in the open's round. Idle indices and idle models make none.
- **Write:** one model-document GET per node per model per TTL while writes arrive, and the blob GET at first flush.
- **Index create, delete or put-mapping, model-mapped:** `+1` compare-and-swap on the reference entry; **first flush:** `+1` descriptor swap. **Model delete:** 1 reference read plus one descriptor GET per named index.
- **Train:** `ceil(training-index vector bytes / 8 MiB)` GETs, a retry reads them again; 1 blob PUT; the marker swaps ADR 0086 counts.
- **Heap:** the model resident once per node (`nlist x dimension x 4` plus codebooks: 12.6 MB for 4,096 x 768); each open segment adds its `.ivm` (about 8 bytes a cluster: size and radius) to the `open_indexes` estimate; postings and vectors are paged outside the heap. A query reserves its PQ lookup tables (`m x 256 x 4` bytes per probed cluster in flight, 98 KB at `m` 96) and a scan buffer capped at 1 MiB from `query_execution`; a cluster is read in blocks, not whole.

## Alternatives rejected

- **Faiss's serialization (`lucene-faiss`'s `.faissm/.faissd`).** The index is read whole into memory, with no range access to a list; a node would hold every IVF list of every open segment, which breaks bounded memory, and the sandbox codec has no compatibility guarantee. It stays the way to read a Faiss index a Java node wrote, if a later ADR wants that.
- **A native plugin-tier module that owns its files ([ADR 0080](0080-one-plugin-system-three-tiers.md)).** It would re-implement the pools, the page-cache reads, merges and deletes, and put a C-ABI crossing on every cluster scan. The one thing it would buy, files private to the plugin, is already true of the `.iv*` files.
- **lucene-ivf as it is: centroids embedded in every segment.** A model of 4,096 lists x 768 dimensions is 12.6 MB of centroids; a shard with 100 segments would read 1.26 GB of `.ivm` at open. Model-trained centroids shared per node are also what gives a merged segment the same lists as its inputs.
- **Reading a Java-written `.faiss` segment from a Rust node.** Not needed: ADR 0086 already rules out sharing model-mapped segments with a Java shell. A model-mapped index stays on Rust writers and Rust readers.
- **Always rerank PQ.** Better recall, but an extra round and `.ivv` reads on every query for a feature whose stock behaviour does not; Principle 8 makes it a setting until measured.

## Consequences

- Easier: `_train` has a use, models stop being decoration, and `nprobes` works as the recordings show; one resident model serves every segment and index of its tenant; no per-segment training at flush.
- Harder: four lucene-rust changes land first, each with its own rev bump (a `Cargo.lock` change rebuilds everything cold, so bumps go in their own PRs). The model blob and the vector files are two objects with a CRC tie; a bug there reads codes under the wrong codebook, so the CRC check is a test with a planted mismatch.
- Rules out: sharing a model-mapped index with a Java shell, loading our `model_blob` into Faiss, `cosinesimil` and radial IVF until recorded.
- Deviations from stock, all stated above: `model_blob` is our format and is empty above the document bound; PQ scores are ADC estimates unless the rerank setting is on, as in stock, but not bit-equal to Faiss's.
- Not measured, and the first slices must not claim otherwise: recall of our k-means and PQ against Faiss's at equal `nlist`, `m` and `nprobes`; the `training` pool's default against real `nlist x dimension`; all numbers are provisional while on an emulator.
