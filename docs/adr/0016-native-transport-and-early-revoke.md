# 0016: OpenSearch's native transport, ported, and early revocation of a refused peer

**Status:** Accepted after independent review, 2026-11-16.

## Context

Node-to-node requests come next: a write forwarded to its shard's owner, then searches forwarded to readers, commits and tails pushed to readers, caches warmed from a peer. The Java shell sends all of these over OpenSearch's native transport (`transport/ShardRouter`, `ForwardedWorkHandlers`, `forwarding/Forwarded*Request`): TCP on port 9300, OpenSearch's framing and stream serialization, and an HMAC on every forwarded request (`TransportAuthenticator`). Peers are found through their leases, which carry the transport address the node bound; a node that stops renewing stops being addressable.

The owner chose (2026-11-16) that **Rust and Java nodes forward to each other directly**, so Rust speaks the Java's protocol and no Java change is needed. The alternative weighed and rejected was requests over the Rust HTTP edge, which is simpler but leaves a mixed fleet unable to forward between implementations until a role is wholly Rust.

What the Java puts on the wire (OpenSearch 3.10, shell revision 429b4cbc):

- **Frame:** `E` `S`, a 4-byte big-endian length of the rest, an 8-byte request id, a status byte (request, error, compressed, handshake bits), a 4-byte version id, a 4-byte variable-header length, then the variable header (the thread context's request and response headers; for a request also the feature names and the action), then the message. A length of `-1` with no body is a keep-alive ping. A compressed frame's message is raw deflate behind the marker `DFL\0` (`DeflateCompressor`, level 3); the shell compresses only towards a peer in another zone (`compress_cross_zone`).
- **Connecting** opens 13 channels by default (`ConnectionProfile`: 2 recovery, 3 bulk, 6 regular, 1 state, 1 ping); each sends the TCP handshake (`internal:tcp/handshake`: the sender's minimum compatible version in, the receiver's version out). Then `TransportService` sends `internal:transport/handshake`, whose answer carries the remote `DiscoveryNode` (written with its attributes and roles), a cluster name and a version; the connection is refused unless that node equals the expected one, which compares the ephemeral id from the lease. The cluster name is not checked (`connectionValidator` passes `cn -> true`).
- **Every `TransportRequest` begins with its parent `TaskId`** (a node id string, then a long when it is not empty), the handshakes included.
- **Forwarded actions** come in two kinds. The write, bulk, get, commit, tail and cache actions (`internal:serverless/document/write`, `internal:serverless/commit/push`, `internal:serverless/cache/*` and their kin) are hand-written `Writeable`s of strings, vints, zlongs, booleans and byte arrays. The search actions (`internal:serverless/search/shard`, frozen search, explain) carry OpenSearch's general classes: a `SearchSourceBuilder` with named-writeable queries, aggregations and sorts in, `SearchHit`s and `InternalAggregations` out. Errors come back through `writeException`: a `RemoteTransportException` wrapping an exception chain (registry ids, messages, stack frames, causes, suppressed exceptions, metadata).
- **Authentication:** header `x-serverless-transport-mac` = `generation:sender:timestamp:nonce:mac`, HMAC-SHA256 under the current secret over the tag `serverless-transport-v2`, the action, the sender, the recipient (`node id/ephemeral id`), the timestamp, the nonce (each NUL-terminated), the SHA-256 of the request's serialization (the receiver re-serializes the request it decoded, so an encoding must round-trip byte for byte) and the SHA-256 of the other request headers (sorted, as `writeMap` of strings, without the MAC and legacy token headers). Refused (403) outside a window of one lease lifetime, under an unknown generation (the previous one for one window after a rotation; a newer one probes the secrets register at most once a second, and a probe refused by that limit answers a rejection, 429, not 403), with a wrong MAC, or with a (sender, nonce) already seen; the replay cache holds 65,536 entries and refuses when full. A Java receiver still accepts the legacy `x-serverless-transport-token` header when no MAC is present, and a Java sender without a secret sends it. Writes to a system index also carry `x-serverless-plugin-origin`.

Forces:

- **Metadata never crosses a node.** Node-to-node traffic carries documents, query results and pushes; fencing is the write log's and shard heads' compare-and-swap, so the transport makes no S3 request and is never needed for correctness.
- **Bounded memory** ([ADR 0004](0004-bounded-memory-and-streaming.md)): a frame's bytes are reserved before they are read.
- **No async runtime** ([ADR 0006](0006-http-stack.md)): blocking I/O on bounded thread pools, as the HTTP edge and the S3 client.
- **Hundreds of nodes a fleet:** a Java node connecting to a Rust node opens 13 sockets, so a Rust node may hold a few thousand inbound channels, almost all idle.
- **A crashed writer stalls its shards** for 20 to 40 s, until its lease expires (30 s lifetime, renewed every 10 s). The owner asked for faster failure detection (2026-11-16) and framed writers as "cattle, but a bit more pet". A connection refused by the peer's host (nothing listens on its port) is a much stronger signal than a timeout, which an overloaded or partitioned node also produces.

| Failure detection | For | Against |
|---|---|---|
| **Revoke on a refused connection, confirmed once** (chosen, off by default) | No traffic while healthy; acts only on a signal a timeout cannot fake; one read and one swap per dead node | Catches only a dead process on a live host (crash, OOM kill, restart), not a dead host or a partition |
| SWIM-style ping, indirect probes, then revoke | Catches dead hosts and partitions in seconds | Pings from every node; cannot tell dead from overloaded, so a busy node is kicked and its shards move under load; needs a soak to tune |
| A hot standby writer per shard, tailing its write log | Near-zero replay at takeover | Memory and CPU on a second node for every hot shard; needs the write log and replay first |
| Shorter lease lifetime | Simple | Every node renews more often all the time: half the lifetime, twice the swaps |

## Decision

1. **A new crate, `oss-transport`, at layer 1**, depending on `oss-mem` and `oss-types` only. It owns the stream primitives (`StreamInput`/`StreamOutput`'s encodings: vint, vlong, zlong, strings, string arrays and maps, optional values, versions, `TaskId`), the frame codec with the thread-context headers and features, the two handshakes, `DiscoveryNode` written with its attributes and roles, exceptions (reading any chain within a bound; writing at least `OpenSearchSecurityException` 403, `OpenSearchRejectedExecutionException` 429 and `ActionNotFoundTransportException`), the client, the server and the authenticator. The message formats of each forwarded action live with it, one module per action family, and each round-trips byte for byte with the Java's `writeTo`, because the MAC digests the receiver's re-serialization. The roles above register handlers and call the client. Every encoding is tested against bytes the Java's own classes wrote (`fixtures/transport/`), as the blob formats are.
   **Ported by action, hand-written ones first:** writes, bulk, get, commit, tail and cache actions in both directions now; the search actions, which need OpenSearch's query DSL in binary form, come with the coordinator's search forwarding. A node answers an action it does not decode with `ActionNotFoundTransportException`, as a Java node answers an unregistered action.
2. **The wire is the Java's, at the versions the fixtures cover.** A Rust node announces the version id of the Java shell it is built against (3.10.0 today) and accepts only peers at a version its fixtures cover (3.10.0 today), refusing any other in the TCP handshake: OpenSearch's wider compatibility rule would mean writing every `onOrAfter` branch for every compatible version. It answers both handshakes (the cluster name it answers is the node's `cluster.name`; it does not check the peer's, as the Java does not), and answers keep-alive pings. It reads compressed frames (deflate behind `DFL\0`) and compresses its own towards a peer in another zone, as the Java. Only the native protocol: the experimental protobuf transport and TLS are out of scope; TLS on transport comes with the security work, through the same channel type.
3. **Frames are bounded and reserved, and a whole frame is held: a bounded exception to [ADR 0004](0004-bounded-memory-and-streaming.md)'s streaming.** A request cannot be acted on before its MAC, which digests the whole message, is checked, so the message is read whole. A frame is at most `transport.max_frame_bytes` (100 MiB by default: the shell forwards a shard's part of a bulk in one frame, and the edge accepts bulk bodies up to 100 MiB). The 23-byte fixed header is read first; then the variable header, capped at 64 KiB, is reserved and read, and the cheap authentication checks (decision 6) run on it; only then is the message reserved from `Pool::Transport` and read. The worst case is `Pool::Transport`'s size divided by the frame bound in concurrent largest frames; past that, reservations fail. A frame past the bound, or one whose reservation fails, is read and discarded through a fixed buffer and answered with an error for its request id, keeping the channel open, as the Java's `InboundAggregator` does: closing one channel drops the Java's whole connection to the node, all 13 channels and every request in flight on them. A compressed message (raw deflate, which declares no inflated length) inflates into chunks reserved from `Pool::Transport` one at a time and is refused when its output reaches the frame bound.
4. **The server is blocking, with a reader thread per inbound channel and a shared worker pool.** Each accepted channel gets a reader thread (small stack) that reads whole frames and hands requests to `transport.workers` workers (bounded queue; a full queue answers a rejection the Java maps to 429). A channel's writes are serialized by a lock on its write half, with a write deadline. Channels are capped by `transport.max_inbound_channels`, 16 for each of ADR 0015's `max_members` by default (8,192 at 512 members, room for the Java's 13 a peer); past the cap a connection is accepted and closed. An inbound channel that has not completed its TCP handshake within 10 s, or has carried no frame for `transport.inbound_idle_timeout` (5 minutes; Java connections are long-lived and reconnect on demand), is closed, so idle sockets held by anyone cannot lock the peers out. Handlers run on workers and never wait on a transport call of their own. If a measurement shows the reader threads' memory matters at fleet size, the reader becomes one readiness loop; handlers, frames and the client do not change.
5. **The client is blocking, pooled per peer and bounded.** Towards any peer, Rust or Java, it opens the channels it needs, not the Java's 13: up to `transport.connections_per_peer` (4) sockets, each multiplexing requests by request id with one reader thread routing responses to their waiters. Connect and handshake each carry the caller's deadline (the Java's lesson: a frozen process accepts TCP and hangs the handshake). Failures are told apart: `Refused` (the connect failed with `ECONNREFUSED`: the peer's host answered that nothing listens; `EHOSTUNREACH` and `ENETUNREACH` are `Timeout`), `Timeout`, `Io` (reset or closed mid-call), `Busy`, `Remote` (the peer answered an error, with its type, message and status), `Unauthorized`, `TooLarge`. Retrying is the caller's choice, never the transport's. A global cap (`transport.max_outbound_sockets`) bounds the client's sockets.
6. **Every forwarded request is authenticated as the Java does it**, the same header, MAC, window, generations, probe limit and refusal words, so either implementation verifies the other. Cheap checks run before the frame is read whole where they can (the header is in the variable header, ahead of the message): a missing or malformed header, a timestamp outside the window, or an unknown generation refuse without buffering the message. The replay cache's capacity is a setting (65,536 by default, fixed-size entries: a 16-byte nonce, the sender's hash and an expiry); full refuses rather than forgets. A probe refused by the once-a-second limit answers a rejection (429), as the Java. Rust always signs and does not accept the legacy token header: a deliberate difference, since every Java node at the ported revision with a secret signs, and a Rust node without a secret refuses every forwarded request (closed, not open). The system-index origin header is carried and covered by the headers digest as the Java does. The secrets come from the Java's secrets register, read by the node; its probe reads (at most one a second, only on an unknown generation) go into [request-budgets.md](../request-budgets.md) as a per-node row when the node wiring reads it.
7. **Early revocation of a refused peer, behind `cluster.lease.early_revoke` (node scope, off by default).** When a forward to a lease's holder fails `Refused`, the caller may ask `oss-cluster` to revoke that lease before it expires. It does only when all hold:
   - the lease read now still names the process the call went to (same ephemeral id and address);
   - that lease was renewed at least 2 s ago, taking last-renewed as expiry less lifetime and allowing the clock skew the lease protocol already tolerates;
   - a bare TCP connect at least 500 ms after the first refusal is refused too (a timeout or success cancels it);
   - no revocation of that (node, ephemeral id) is in flight on this node (single-flight), and none was declined in the last lifetime (a negative cache, bounded by `max_members`).
   Before the setting may be turned on, a Java node's shutdown order is checked: if it closes its transport before releasing its lease, a cleanly stopping Java node would be revoked, which is harmless (a handover it was about to cause anyway) but is counted. Then the lease is swapped to a revoked copy at the generation read, as an expired one is today, and the shards are taken by the normal takeover. A timeout, a reset mid-call or an error never revoke. The revoked process does not renew over a revoked lease (`Revoked`, ADR 0015) and enrols again only under a new ephemeral id; a node binds its transport listener before it writes its first lease and keeps it until its lease is released, so a live node's port never refuses. Off by default until the shell's takeover and fencing suites pass with it on and the stall cut is measured (a false positive costs a needless handover, never two writers, because the write log and shard heads fence); then it is turned on by the owner's rule on defaults. Java nodes already treat a revoked lease as dead and take part in the takeover unchanged.
8. **Not built now: ping-and-vote and the hot standby.** SWIM-style pings with indirect probes would come behind `cluster.failure_detector.ping`, off by default until a soak shows host-loss stalls cut and no overloaded node kicked. A hot standby writer (a second node tailing a shard's write log; memory and CPU only, no S3 request) is an option once the write log and replay exist, behind a per-index setting.

## Consequences

- No S3 request is added while the fleet is healthy; idle nodes make no transport calls (keep-alive pings are the Java's, off by default). An early revocation costs one lease read and one swap a detecting node, and one swap wins when several detect at once.
- Memory: frames come from `Pool::Transport` and are reserved before they are read, a message only after the cheap authentication checks pass, so concurrent transport traffic is bounded by that pool; reader threads and sockets are bounded by the two channel caps and the idle timeouts.
- Rust and Java nodes forward to each other in both directions, so a mixed fleet needs no role routing for transport, and the Java's authentication properties carry over: a captured request authenticates nothing else, cannot be replayed within the window or used after it, and a key stops working one window after the next rotation.
- The cost is a port of OpenSearch's wire format: the stream encodings, the frame, two handshakes, `DiscoveryNode`, exception wrapping, and each forwarded action's format, all pinned by Java-written fixtures. A change to OpenSearch's version or to a forwarded action's `Writeable` is a change here too; the fixtures fail when the Java changes.
- A crashed process on a live host can be detected in about one forward plus 500 ms instead of up to a lease lifetime, once the setting is on. Other nodes see the revocation at their next membership refresh, from the digest the lowest-id live member rewrites every third of a lifetime (ADR 0015), so up to 10 to 20 s can sit on top before every node agrees; the end-to-end takeover time is a target until measured on the emulator. A dead host or a partition still waits for expiry.
