# Geospatial, native: geo fields, geo queries and aggregations, `ip2geo`, GeoJSON upload

## Serves

The "Geospatial" row of [java-dependencies](../../java-dependencies.md), which says "partly native". **That is overstated and this spec corrects it:** `geo_point` and `geo_shape` are in `OTHER_TYPES` of `crates/doc/src/mapping/types.rs` (the writer does not index them) and read back as `FieldType::Unsupported` (`mapping_tests.rs`); `geo_bounding_box`, `geo_distance`, `geo_polygon`, `geo_shape` and the geo aggregations appear only in the registered-name lists that feed "did you mean". There is no geo query or aggregation. Owner rule (2026-11-28): native, no Java in the runtime path.

## Change

lucene-rust already has the engine side: `LatLonPoint`, `XYPointField`, the doc-values fields and the shape fields in `lucene-index/src/document/` (`geo.rs`, `shape.rs`, `shape_doc_values.rs`), and queries, sorts and distance features in `lucene-search/src/document/geo/` (`shape_queries.rs`, `sort.rs`, `distance_feature.rs`), plus `lucene-spatial3d`. This spec wires them, then ports the plugin.

1. **Fields.** Index `geo_point` (every input form: object, `"lat,lon"`, geohash, array `[lon, lat]`, WKT point, GeoJSON point; arrays of them) as `LatLonPoint` plus a doc value, with `ignore_malformed`, `ignore_z_value`, `null_value`; read back through `_source`, `fields` and `docvalue_fields`. `geo_shape` (GeoJSON and WKT of point, linestring, polygon with holes, multi-types, envelope, circle where the stock set allows it, geometry collection) tessellated into the shape field, with `orientation`, `ignore_malformed`, `coerce`. `xy_point` and `xy_shape` the same way. Replaces the two `OTHER_TYPES` entries.
2. **Queries.** `geo_distance` (`distance`, `distance_type`, `validation_method`), `geo_bounding_box` (including `top_left` and `bottom_right`, `wkt`, and a box crossing the dateline), `geo_polygon`, `geo_shape` with `relation` `intersects`, `disjoint`, `within`, `contains` and an inline or an `indexed_shape` reference (one document read through the reader, not a LIST), `xy_shape`. Sort: `_geo_distance`. Script fields and `distance_feature` on geo points.
3. **Aggregations.** `geo_distance` (ranges), `geohash_grid`, `geotile_grid`, `geohex_grid`, `geo_bounds`, `geo_centroid`, with shard partials that merge at the coordinator by the pipeline the metric and bucket aggregations already use.
4. **`ip2geo` datasource and processor.** `PUT|GET|DELETE /_plugins/geospatial/ip2geo/datasource/{name}`, `PUT .../datasource/{name}/_settings`, `GET .../ip2geo/_stats`-equivalent; an ingest processor `ip2geo` (`datasource`, `field`, `target_field`, `properties`, `ignore_missing`). The endpoint (default the stock GeoLite2 City manifest) is fetched with the plugin system's `egress:<host>` rule: allow-listed host, no redirect, private and loopback addresses refused after resolve, bounded body. The downloaded CSV is turned once into a **sorted range table** stored as blobs under `geospatial/ip2geo/<name>/<version>/`: a small top-level index (the first 16 bits of the address to an offset, at most 512 KiB held per datasource) and fixed-width records. A lookup is one ranged GET of the bucket the top-level index names, after the datasource's version marker and top-level index are held; a node caches the top-level index and recently read buckets within a pool reservation. No index is created and no search runs for a lookup.
5. **GeoJSON upload.** `POST /_plugins/_geospatial/geojson/_upload` (`index`, `field`, `type`, `data` of features; at most 10,000 features and 8 MiB a request) turns features into a bulk of documents through the ordinary write path, creating the index with the mapped geo field when it does not exist. `GET /_plugins/_geospatial/_stats` answers the request counts of this node.

Not here: map tiles and vector tiles (`_mvt`; a separate API, listed unserved), `h3` and `geo_grid` queries beyond `geohex_grid`, reverse geocoding, and any datasource other than the two the plugin ships (the GeoLite2 City and Country manifests; a custom CSV manifest is accepted for the same schema).

## Acceptance criteria

- AC-1: every `geo_point` input form above indexes to the same encoded point, an invalid latitude or longitude is a 400 naming the field (or is skipped with `ignore_malformed`), and the value read back through `_source`, `fields` and `docvalue_fields` is what OpenSearch returns, checked against recorded outputs of the stock server (`fixtures/geo/`, recorded once and replayed).
- AC-2: `geo_distance`, `geo_bounding_box` and `geo_polygon` return the same ids as stock for a fixed corpus of at least 1,000 points including the dateline, the poles and boundary-equal points; a geo query on a field not mapped as geo is 400, and `ignore_unmapped` is honoured.
- AC-3: `geo_shape` with each relation matches stock on a fixed corpus of polygons (with holes), multipolygons and lines, including a shape crossing the dateline and an `indexed_shape` reference, which makes one document read and no LIST.
- AC-4: `geohash_grid`, `geotile_grid`, `geohex_grid`, `geo_bounds`, `geo_centroid` and `geo_distance` aggregations equal stock's on the corpus, and a two-shard answer merges to the one-shard answer.
- AC-5: `_geo_distance` sort orders by metres in `unit`, with `mode` and `distance_type`, ties broken by the stock rule, and a missing value last by default.
- AC-6: the ip2geo processor annotates a document with the range's properties, leaves an address outside every range with no target, honours `ignore_missing`, and an invalid address is a 400 for the document, not the bulk.
- AC-7: building a datasource from the recorded GeoLite2-shaped CSV fixture (no network) and then looking up addresses makes at most 3 sequential round trips cold (version marker, top-level index, bucket) and 0 requests warm; **a bulk's lookups are bounded per request**: a bulk of 10,000 documents with random addresses reads at most `serverless.geospatial.max_buckets_per_request` (default 64) distinct buckets, fetched together in one round, and a document whose bucket is beyond the bound is annotated with nothing and counted in the response's `ip2geo_skipped`, asserted by a cold-bulk request count; buckets are about 1 MiB; the table for 3,000,000 ranges is built in bounded memory (counting allocator, at most 64 MiB, streaming) and held at most 512 KiB + the pool's cached buckets.
- AC-8: the download is refused for a redirect, a private resolved address and a body over `serverless.geospatial.max_download_bytes` (default 512 MiB), each leaving the previous version in place; the swap to a new version is one compare-and-swap, and a lookup never sees a half-built table.
- AC-9: **no standing cost without a datasource**: an idle node with none makes zero requests; a datasource holds at most 10 per tenant; a refresh runs at `update_interval_in_days` (default 3, floor 1) claimed by the shared scheduler, not by a poll (**blocked** on `oss-meta::schedule`, alerting slice 5: until then refresh is an explicit `_settings` or `_update` call and no timer ships), and a refresh that finds an unchanged manifest `version` costs the manifest GET alone.
- AC-10: GeoJSON upload of 10,000 features makes the requests of one bulk of that size and creates the index with the mapped geo field only if absent; a feature that does not parse is reported by index in the answer, not a whole-request failure; over the bounds is 413.
- AC-11: with `serverless.geospatial.index_fields` off (the old mode) a geo field maps and is kept in `_source` as today, is not indexed, and a malformed geo value is accepted as today; with it on a malformed value is 400 unless `ignore_malformed`; an index created in the old mode keeps the old behaviour, and segments without points answer geo queries with no match, never an error; both modes run in CI and the existing suite passes unchanged. With `serverless.geospatial.enabled` off the ip2geo and upload routes answer 400 `no handler found`.

## Test plan

Slices 1 to 3 differential against recordings from stock OpenSearch (the Java recorders under `fixtures/` produce bytes once; the Rust tests replay them with no Java), the differential-testing approach where a recorder exists, otherwise hand-built cases whose expected ids are computed by a brute-force haversine oracle in the test, red first by the current `Unsupported` mapping. Slice 4: the CSV fixture is a small file of the same schema; a build-time property test compares the table lookup with a linear scan over the ranges. Egress rules reuse the plugin system's tests.

## S3 request budget

Fields, queries and aggregations add none beyond a search's. ip2geo: a lookup cold is 1 GET for the top-level index per datasource version and 1 ranged GET per bucket, warm 0; a refresh is the manifest GET, the download (not the store), the table's PUTs (one per 1 MiB of records, so bytes, not documents) and one marker swap, then the previous `<version>` directory is queued to the janitor's reclaim after a lookup grace. Idle makes zero. Rows go in [request-budgets](../../request-budgets.md).

## Switch

Fields, queries and aggregations: `serverless.geospatial.index_fields` (`OSS_GEOSPATIAL_FIELDS`), per index at create with a cluster default. Default **off** until measured: indexing a geo field adds index size and index-time work, and rejects malformed values that are accepted today, which is a downside by the switch rule. It flips on when the measurement (index size and ingest p99 on a geo corpus, provisional on the emulator) shows both within 5%. Tessellation limits are settings (`serverless.geospatial.max_shape_vertices`, default 10,000). ip2geo and upload routes: `serverless.geospatial.enabled` (`OSS_GEOSPATIAL`), default **off** until AC-6 to AC-10 pass, then **on**: the datasource exists only when a person creates one, so an unused install costs nothing.

## Risks

- Tessellation and relation semantics are subtle (dateline, poles, hole orientation); recorded stock outputs are the guard, and a mismatch is a bug to fix, not a tolerance to widen.
- lucene-rust's geo query coverage must be confirmed per query type before slice 2 starts; a gap is a lucene-rust task first and the slice waits.
- The table build assumes the CSV is sorted by range start (GeoLite2's is); an unsorted one is refused 400 at build rather than sorted in memory.
- The GeoLite2 data licence and manifest URL are the operator's: the default endpoint is the stock one and is named in the datasource, nothing is bundled.
- `geohex_grid` needs an H3 implementation; if none exists in lucene-rust it is a separate slice and refused 501 until then.
