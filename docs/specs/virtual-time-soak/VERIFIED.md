# Virtual-time soak: verified

Slice 1, run in the cloud sandbox (4 cores, debug build, emulator with latency off):
`cargo test -p oss-node --features writer --test virtual_soak -- --nocapture`. Times are provisional.

The run: 21 cycles of 8 virtual hours (7 virtual days), seed `0x5eed`, on one `VirtualClock` shared by every node, lease handle, head store and the collector. Each cycle a live owner writes, renews its lease through `LeaseKeeper::renew` every virtual minute and publishes now and then; it then stops (a kill, or a freeze that thaws after the take-over); the next node takes the shard from the lease (`Takeover::from_leases`), and a `DeadLogPass` collects the dead node's log. Shards merge as shipped. Result: 5,069 acknowledged documents, slowest take-over 30,000 ms of virtual time, 4 thawed owners refused, 21 logs collected, 2.2 s of wall time.

No product code changed: every lifecycle step of this slice already took its clock (`LeaseClock` for membership and heads, a closure for publishing and the dead-log pass). The rig change is `node_with_clock` in `tests/proactive_support/packed.rs`, which `node_with_packs` now calls with the clocks it always used, and a `keeper` field on the rig's `Node`.

- AC-1: `a_week_of_kills_and_freezes_loses_nothing_and_collects_every_dead_log` (crates/node/tests/virtual_soak.rs). Every acknowledged write's sequence number must be the count acknowledged before it, so a lost or doubled document across any take-over fails at once; 21 take-overs, 4 of them with a frozen owner that wrote after the thaw and was refused. Seen red: taking over without the predecessor's log (`member(n, false)`) fails with "no take-over in ten leases". NOT-RUN: a read of the documents themselves (the count is by sequence number), and the read on every live node.
- AC-2: `a_week_of_kills_and_freezes_loses_nothing_and_collects_every_dead_log` again: the first acknowledgement after each stop came within the lease TTL (30,000 ms) of the stop, at a 5 s step; the last third's slowest is checked against twice the first third's plus a lease. Seen red: renewing the dead owner's lease through the take-over fails with "no take-over in ten leases".
- AC-3: `a_week_of_kills_and_freezes_loses_nothing_and_collects_every_dead_log` again: after each cycle the collector, stepped 4 minutes a try, removes every blob of the dead node's log (`nodelog/<node>/`), which the test counts by LIST in the test only. A dry run fails it (seen red: the pass run dry leaves 17 blobs). The live owner is not collected: its next cycle writes through its log. One finding: without merging the commit register grows about 3 KB a take-over and passes the rig's 64 KiB read buffer at the nineteenth, so the rig enables merging as the node ships it.
- AC-4: `a_blob_goes_only_after_its_whole_window_and_every_one_goes_in_a_week` and `a_dry_run_over_the_week_deletes_nothing` (crates/janitor/tests/virtual_lifecycle.rs): 168 unreferenced blobs of an older term, one an hour for seven virtual days, a sweep every five minutes under a one-hour window; each goes no earlier than its window and within two sweeps after it, the blob the live manifest names never goes, and a dry run deletes nothing. The rule tested is the garbage collector's (two sightings and `minimum_unreferenced_millis`); the orphan-shard sweep has no age rule, so it is not covered. Seen red: window 0 fails with "went after 300000 ms, before its 3600000 ms window". NOT-RUN: the collector's own relist scope over the week (`relist_after_millis` is 0 here).
- AC-5: `a_point_in_time_lives_to_its_deadline_and_pins_its_blobs_until_then` (crates/janitor/tests/virtual_lifecycle.rs): six views with keep-alives from one to 72 virtual hours, two extended before their end and one refused an extension after it; at every five-minute step each is live exactly while `now < deadline` (to the millisecond of the boundary), and the blob a view pins is never deleted by a sweep while the view is live and goes after it. Seen red: pins ignored fails "view 0's blob was deleted while it was live"; a clock five minutes behind fails at the first deadline. NOT-RUN: the typed error a search by an expired id answers (a node route, not exercised here).
- AC-6: `a_week_of_passes_over_idle_held_shards_asks_for_nothing_and_does_not_grow` (crates/node/tests/virtual_idle.rs): a writer holding four published shards, its publish, hibernate and janitor passes every virtual 15 s (janitor each minute) for 168 virtual hours with the node's shipped one-hour relist: zero requests in every hour, 0.3 s wall (debug, provisional). Control: after the week a written document makes the same passes ask the store for something within an hour, so the zero is not a loop that does nothing. Seen red: a document written before the week fails with `[6, 0, 0, ...]`. NOT-RUN: lease renewal over the week (it is node-level and counted in slice 1's rig), and reader-side idle shards (the reader has no periodic check yet).
- AC-7: `crates/node/tests/realtime_soak.rs`, the soak's driver on the real `SystemClock` with a 2 s lease (the rig's node builder in `crates/node/tests/proactive_support/packed.rs`, which the older builder now calls with the shipped 30,000), a real timer thread per node renewing every 250 ms beside the writes, real sleeps in the take-over poll and the collection. `two_real_time_cycles_lose_nothing_and_collect_every_dead_log` runs on every push (2 cycles, about 10 s wall); `a_minute_of_real_time_kills_and_freezes_loses_nothing` is `#[ignore = "slow"]`, so the nightly tier runs it (10 cycles, about 55 s wall, a frozen owner refused). Provisional, emulator, 4-core container, debug build: take-overs 1,757 to 1,769 ms real against the 2,000 ms lease, so about 0.88 of the lease; the virtual run's were exactly the lease at a 5 s step, so the two agree to within the timer step. Seen red: a timer that renews every 3 s (longer than the lease) makes the first take-over come after 2 ms, and the lower bound (a take-over before the lease could run out) fails it. Two bounds hold: nothing lost or twice and every dead log collected (AC-1, AC-3), and the slowest take-over within a lease plus two polls plus 1,500 ms for a loaded runner (AC-2). The driver is copied from `virtual_soak.rs`, not shared, so that file stays free for the slice that extends it; the two drift apart only by their clock.
  What it holds that the virtual run cannot: real thread scheduling between a renewing timer and the writes, real sleeps, a lease that expires by elapsed time. What it does not: a run of more than about a minute, so no drift, memory or descriptor growth over days; a real store.

Not covered by this slice and said in the spec: memory, descriptor and thread drift, real latency and `Instant::now` timeouts, a real store, a mixed fleet, clock skew between nodes, the pack collector.
