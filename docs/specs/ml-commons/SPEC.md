# ML Commons, native: model groups, connectors, remote and local models, then agents and memory

## Serves

R15.4's ML Commons plugin, under [ADR 0079](../../adr/0079-ml-commons-is-ported-natively.md), which supersedes [ADR 0046](../../adr/0046-plugin-requests-are-proxied-to-java-nodes.md) for it (the owner's decision, 2026-11-28: port the other plugins as learning to rank was). Follows the shape of [ltr](../ltr/SPEC.md); tasks are node-local memory ([ADR 0072](../../adr/0072-tasks-are-node-local-memory-with-no-blob-requests.md)).

## Change

Five slices, one PR each (slice 1 also the crate scaffolding), on by default, with `serverless.ml.enabled` as an off switch. The model work is not rewritten: `lucene-ml` (huyz0/lucene-rust, the revision the workspace already pins) holds the ONNX and TorchScript runners, the tokenizer, the text-embedding, sparse, cross-encoder and highlighting models, the connector engine (substitution, JsonPath, pre/post-process functions, SigV4, Google tokens) and the credential cipher, each checked against vectors recorded from a stock node. Its Java caller (lucene-rust's plugin `ml` package, 11,000 lines over `.plugins-ml-*` indices) is the **reference for shapes and errors**, ported to Rust over blobs. Routes are `/_plugins/_ml/...`.

1. **Store, model groups, connectors** (1a model groups and the claim blobs, 1b connectors and their credentials). A `ml/` document tree (the `DocSet` of the LTR store): `model_groups`, `connectors`, `models`, each object a blob written by compare-and-swap, a marker per set, nothing listed. Routes: `model_groups/_register`, `PUT|GET|DELETE model_groups/{id}`, `model_groups/_search`; `connectors/_create`, `PUT|GET|DELETE connectors/{id}`, `connectors/_search`. Connector credentials are encrypted at rest as stock stores them (`lucene-ml` `esdk`), with a master key blob created once by conditional create. Access control: stock's `backend_roles` and `access_mode` are read and refused 400 unless the security layer is on; with it on they go through the existing authz.
2. **Remote models.** `models/_register` (remote, with a `connector_id` or an inline `connector`), `GET|PUT|DELETE models/{id}`, `models/_search`, `models/{id}/_deploy`, `_undeploy`, `models/{id}/_predict` and `_predict/{algorithm}/{id}` for `REMOTE`, `tasks/{id}` GET and DELETE, `tasks/_search`. A register or deploy returns a task id and runs as a task of [ADR 0072](../../adr/0072-tasks-are-node-local-memory-with-no-blob-requests.md)'s registry unchanged: id `<node>:<n>`, 32 running and 128 kept, the 64 KiB reservation, a read of another node's id forwarded to that node over the transport. ML adds no task registry and no task settings. Every outbound fetch of a user-supplied URL (connector calls, MCP and tool calls, local-model URL register) goes through one client: https only, no redirects at all, the host matched against `trusted_connector_endpoints_regex` (default deny-all: an empty value allows nothing), the name resolved once per call and the connection pinned to that address, which is refused when loopback, link-local (169.254.0.0/16, fe80::/10), unique-local, unspecified, multicast or an IPv4-mapped form of any of these, unless `private_ip_enabled`; credentials are sent only to the host they were configured for. A request timeout, a response byte bound and a per-node concurrency bound apply to all of them. Predict reads the model and its connector through a TTL cache (the LTR model cache's shape).
3. **Local models.** `lucene-ml`'s `TEXT_EMBEDDING`, `SPARSE_ENCODING`, `SPARSE_TOKENIZE`, `TEXT_SIMILARITY` and `QUESTION_ANSWERING` for ONNX and TorchScript, from `models/_register` (a pre-trained name, a URL, or `models/meta` plus `upload_chunk`). Model files are blobs under `ml/artifacts/<model>/`, streamed in and out, never held whole; a deployed model is charged to the memory pool before it loads, and `max_model_on_node` bounds how many a node holds. ONNX Runtime and libtorch load from the paths the settings name; absent, local registration is 400 and says so.
4. **Stats, profile, tools.** `stats`, `profile`, `profile/models`, `profile/tasks` for this node (`_nodes.total` is 1, no fan-out), `tools`, `tools/{name}`.
5. **Agents, memory, containers, MCP.** Agents (`flow`, `conversational_flow`, `conversational`, `plan_execute_and_reflect`, `ag_ui`) and their tools, `memory` and `memory_containers`, MCP connectors, ported from `MlAgents`, `MlAgentRunner`, `MlChatRunner`, `MlPlanRunner`, `MlMemory`, `MlMemoryContainers`, `MlMcp`. Memory is documents in an ordinary index of the cluster (the stock `.plugins-ml-memory-*` names) through the existing index and search paths, not a new store. Specified in detail when slice 5 lands; criteria AC-15 and AC-16 below bound it.

Not here: `_train`, `_predict` and `_execute` for k-means, RCF, linear regression and the other classic algorithms (no stock user of the serverless scope needs them; each is a refusal 400 naming the algorithm); the neural-search ingest processors, `neural` query and rerank processor, which are a separate plugin that calls this one; model hosting on GPU; Java-shell interop (Java nodes do not read the Rust store). The proxy's `/_plugins/_ml` prefix stays while the switch is off and leaves the list when the default turns on; a route beats a prefix, so a node with the switch on serves what is native and proxies the rest.

## Acceptance criteria

- AC-1: a model group is registered, read, updated, searched and deleted with the response shapes in `shapes.md` (the stock 3.10.0 recording, `fixtures/stock-plugins/ml.json`; `shapes.md` is not needed); registering a name that exists in the same access scope is 400 as stock does.
- AC-2: a connector's credential is never returned by any route and is stored encrypted: the blob holds no byte of the plaintext, and a stock-produced ciphertext decrypts (the vector `lucene-ml` already carries).
- AC-3: a connector definition that fails stock's validation (missing `protocol`, `actions`, a non-https endpoint, an endpoint outside `trusted_connector_endpoints_regex`, a private address with `private_ip_enabled` false) is refused 400 with stock's message, at create, never at predict.
- AC-4: a connector or model put costs 1 GET and 2 PUTs, a model group put 1 GET and 3 PUTs (its name claim, below), a get 2 GETs, a search reads the marker and then, for each object it looks at, the marker again and the object (`DocSet::get`, as the ISM list does): 2 GETs a hit, at most 100 hits a page, and none lists; asserted by the meter. Name uniqueness in an access scope (a model group's name) is a claim blob keyed by a hash of the scope and the name, made by conditional create, so no LIST finds a duplicate; a delete releases it, a rename claims the new name first and then releases the old, and a claim left by a put whose object write failed is released by the same request's error path and, if that fails too, is reused by the next put of the same name by the same caller (the claim blob records the object id it was made for, so an orphan is recognised without a LIST). A set's marker holds object ids; a set is bounded by the document set's own 1,000 documents (`MAX_DOCS`, not a setting), a put past it is 429, and a search by name words, or sorted by name, reads every group, so it is refused (400, naming the exact `name.keyword` term to use) past 200 groups, a constant `TOKEN_SCAN_MAX`.
- AC-5: registering a remote model returns `{task_id, status: "CREATED", model_id}`; the task reaches `COMPLETED` with the model `REGISTERED`; `_deploy` then `_predict` runs the connector's request against a local HTTP fixture server and returns the shape stock returns (`inference_results[].output[]` with `name`, `data_type`, `shape`, `data`); a model not deployed is 400 with stock's text, and undeploy then predict is the same 400.
- AC-6: a predict's outbound request equals the request stock would build for the same connector and input: URL, headers, body and (for an AWS connector) the SigV4 signature, over the vectors `lucene-ml` records; a response past `serverless.ml.max_response_bytes` is cut and refused 502, never held whole.
- AC-7: a remote call times out at `serverless.ml.remote_timeout_ms` with 408-class stock text; more than `serverless.ml.max_remote_calls` in flight on a node queue to a bound and then 429, never an unbounded task or thread.
- AC-8: a task is ADR 0072's: `tasks/{id}` for a finished task on this node answers, an evicted or restarted one is 404 `resource_not_found_exception`, another node's id is read from that node over the transport; a 33rd running task is 429; making and reading tasks makes 0 object-store requests (ADR 0072).
- AC-9: with a mocked clock, a model or connector replaced through another node is not seen before `serverless.ml.cache_ttl` and is seen by the first predict after it; a warm predict makes 0 object-store requests; a cold one makes 4 GETs (model, its group marker, connector, master key) in at most 2 rounds; steady cost is at most (models used) x (nodes) over the TTL, independent of predict rate.
- AC-10: a `TEXT_EMBEDDING` ONNX model returns, for each recorded input, the vector `lucene-ml`'s stock recording holds within 2e-5 relative; the same for `SPARSE_ENCODING` (weights by token), `TEXT_SIMILARITY` (score) and `QUESTION_ANSWERING` (highlights).
- AC-11: a local model's memory is reserved before it loads, charged at its file bytes plus the runner's recorded overhead factor; one past the pool's remaining bytes, or the `max_model_on_node` count, is refused 429 at deploy with stock's text, and undeploy returns every reserved byte (the pool's counter equals its value before the deploy).
- AC-12: a model file larger than 1 GiB streams through `upload_chunk` and a URL register with the process's peak resident memory under 64 MiB above its idle, measured by the allocator and recorded; no request body is read whole.
- AC-13: on `oss-ml`'s own request path (parsing, connector rendering, result shaping; not ONNX Runtime or tokenizer internals, which the memory pool charge covers) allocation after warm-up comes from pooled buffers or carries an `ALLOC:` bound, shown by the counting allocator, and a predict that waits for a runner occupies no thread beyond the pool's bound.
- AC-14: `tools` lists the registered tools and `tools/{name}` answers one or 404; `stats` and `profile` count registrations, deploys, predict requests and failures, per model and for the node; a named stat answers only itself and an unknown one is 400; an unknown route under `/_plugins/_ml` is 400 `no handler found`.
- AC-15: an agent run through `agents/{id}/_execute` makes only the calls its tools name, each a predict, a search or a get through the paths above, and stops at `max_steps`; the run's total outbound calls and tokens are bounded by settings and a run that would pass them is refused with a typed error.
- AC-16: memory (conversation and container) writes are ordinary index writes, so a write costs what a one-document bulk costs and an idle container makes 0 requests.
- AC-17: with `serverless.ml.enabled` false every route answers as today (to a plugin upstream when one is configured, else 400 `no handler found`); with it true and the security layer on, each route needs the permission stock names for it.
- AC-18: a request body past `serverless.ml.max_request_bytes` is 413 before it is read whole; a malformed body is 400 with the parse position, never a panic.
- AC-19: the outbound client refuses, with a typed 400 and no connection made, each of: an http URL, a host outside the allow-list, an empty allow-list, a name that resolves to loopback, 169.254.169.254, a unique-local or an IPv4-mapped private address, and a redirect of any status; a name that resolves differently on a second lookup still connects only to the first address; a credential is absent from a request to any other host. The same cases run through MCP, tool and local-model URL calls. A URL fetch past `serverless.ml.max_fetch_bytes` is cut and refused.
- AC-20: a set past the document set's 1,000 documents is refused 429, and a name-word or sorted search over a set larger than 200 groups is refused 400, asserted by the meter (an exact `name.keyword` term reads the name's claim and one object, so 4 GETs); a `size` past `max_search_size` is 400.

## Test plan

Every criterion's test is written first and seen red against a stub. Slice 1: unit tests over the `DocSet` shape and the encryption vectors; route tests on the in-process emulator with the counting meter (AC-4 red by an extra GET). Slice 2: a local HTTP fixture server standing for OpenAI-shaped, SageMaker-shaped (SigV4 checked by recomputation) and Bedrock-shaped endpoints; AC-6 compares to the vectors from `lucene-ml`; AC-7 with a server that never answers. Slice 3: stock vectors carried as fixtures with the command that made them (a stock node run is not available in this sandbox, so they are the recordings `lucene-ml` already commits); the ONNX Runtime library is a CI download pinned by hash and tests that need it skip with a printed reason when absent, never pass. AC-12 and AC-13 are ignored `--release` tests recorded in VERIFIED.md. Compatibility: the reference plugin's comparison script in lucene-rust already runs one call set against a stock node and the Java plugin; slice 1 adds the same call set aimed at this node, and its output against stock is recorded where a stock run exists, `NOT-RUN` where it does not.

## S3 request budget

Management: the stored-scripts shape (put 1 GET and 2 PUTs, get 2 GETs, no LIST), a row each in [request-budgets](../../request-budgets.md) when a route lands, including the model group put's 1 GET and 3 PUTs. Predict: 0 on a warm node, 4 GETs cold in 2 rounds, steady cost bounded by models used x nodes over the TTL. Artifacts: a deploy reads the model file once per node that deploys it, in ranged GETs of the buffer size (requests scale with bytes); register by URL writes it in parts of the buffer size. Tasks, stats and profile: 0. Idle: 0 (no timer, no poll).

## Crate

`oss-ml` is layer 3, beside `oss-reader` and `oss-writer`, depending only on `oss-types`, `oss-mem`, `oss-blob`, `oss-meta`, `oss-rest` and `lucene-ml`, and never on the reader or writer; `oss-node` (layer 5) mounts its routes. The registry lives in `oss-node` (`ml_route`, as ISM's policy service does) until slice 2 brings `lucene-ml` in; the crate is created then. It then gets its README, AGENTS.md, port-map.tsv and the `architecture.md` and layering-check entries, and marks ADR 0046's ML Commons line as superseded.

## Switch

The owner's rule (2026-11-28): a plugin needs no enable flag, or its flag is on by default. `serverless.ml.enabled` (`OSS_ML`) is on by default and stays only as a node-level off switch for a mixed fleet; with it off, `/_plugins/_ml` goes to a plugin upstream when one is configured. No criterion waits for the flag: each slice's routes are live when it merges, and an idle registry makes no request. Where a slice has a real cost, a bound or an allow-list limits it instead of a flag: outbound fetches refuse every host until `trusted_connector_endpoints_regex` names one (AC-19); local models load only when `onnx_runtime_path` names a runtime and are charged to the memory pool (AC-11); agents are bounded by their own settings (AC-15). The native overhead of predict stays within 5% of the stock plugin's on the same fixture, measured by a benchmark that runs outside `cargo test` and recorded in VERIFIED.md. Other settings (all node scope, bounds with defaults in the registry): `max_request_bytes`, `max_response_bytes`, `remote_timeout_ms`, `max_remote_calls`, `cache_ttl`, `cache_bytes`, `max_model_on_node`, `onnx_runtime_path`, `libtorch_path`, `max_queue` (calls waiting for `max_remote_calls`), `max_fetch_bytes`, `max_search_size` (a search's `size` past it is 400, tested in AC-20), `trusted_connector_endpoints_regex`, `private_ip_enabled`, and for agents `agent_max_steps`, `agent_max_calls` and `agent_max_tokens` a run. Tasks use ADR 0072's bounds.

## Risks

- Stock's source is outside this sandbox; shapes come from the reference plugin's Java, which its own script checks against a stock node. They stay provisional until a stock recording of this node exists.
- `lucene-ml` pulls `ort` (dynamic load) and the `tokenizers` crate with a C regex library: build time and binary size grow, and the dependency is isolated in one new crate `oss-ml` so a node without the feature compiles without it. The first slice measures both.
- A connector is an outbound request to a user-supplied URL: the allow-list regex, https only, no redirects and the bounds above are the defence; a hostile-endpoint test (slow body, huge body, redirect to loopback) is part of slice 2.
- Model files are large and a deploy on every reader is a thundering herd of ranged GETs; the first measure is bytes per deploy, and warm-copy from a peer is a follow-up, not assumed.
- Agents multiply outbound calls per request; slice 5's bounds (AC-15) must be measured before it is on by default.
