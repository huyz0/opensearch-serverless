# Progress (evidence so far; VERIFIED.md is written when every criterion has its line)

Slice 1 (the registry and run claims, `oss_format::alert_registry`, `oss_meta::AlertRegistry`) is built; the monitor store (its documents and the per-tenant monitor index the runner and the removal's question read) comes with slice 2, where the routes need it. Nothing else is built.

- AC-2 (registry part): `registering_costs_one_read_and_one_write_even_when_the_entry_is_there`, `a_removal_costs_one_read_and_one_write` (emulator and S3 on loopback: 1 GET and 1 PUT; the file store adds one ranged read to a swap), rows `alerting.register.requests` and `alerting.unregister.requests` in [request-budgets](../../request-budgets.md). The monitor's own put, read and delete counts are slice 2's.
- Registry protocol (slice 5's "Registry writes"): `a_registration_between_the_removals_read_and_swap_keeps_the_entry`, `a_registration_after_the_removal_adds_the_entry_back`, `a_removal_that_stops_before_its_swap_leaves_the_entry`, `a_removal_that_finds_an_enabled_monitor_keeps_the_entry_and_writes_nothing`, `a_removal_that_keeps_losing_its_swap_gives_up_to_contention`, over the three backends. Seen red against two broken protocols: a registration that skips its swap when the entry is present (3 of the tests failed) and a removal that asks its question only for a never-created shard (4 failed). A remover killed between any two steps is the stopped-before-the-swap test: nothing is written before the swap.
- Run claim (slice 5's "Claim"): `a_slot_is_claimed_once_and_only_upwards` (row `alerting.claim.requests`: a first claim is one read and one create), `a_hinted_claim_is_one_request_and_a_stale_hint_falls_back_to_a_read` (row `alerting.claim_hinted.requests`: with the generation of the node's last claim, one swap), `of_two_claimers_of_one_slot_exactly_one_wins` and `a_claim_that_keeps_losing_its_swap_gives_up_to_contention` (the register moved between a read and the swap, through `claim_between`), `a_damaged_claim_register_is_refused`. Claim registers are never deleted here; removing a deleted monitor's claim is slice 2's.
- Formats: `crates/format/tests/alert_registry.rs` (shard order, bounds, damaged shards refused, tenant id rules, shard hash `registry_shard_of("a") == 0x2c` from FNV-1a, keys, claim bytes). Seen red against a stub of every function (9 of 9 failed).
- Bound: a shard past 4,096 tenants refuses a new tenant (`a_full_shard_refuses_a_new_tenant_and_keeps_a_present_one`); a tenant already named still registers.

Not run: the spec's concurrent soak across nodes (slice 5); the registry's bytes read per TTL at 1 million tenants.
