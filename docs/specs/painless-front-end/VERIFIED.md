# Painless front end: verified (partly)

Run on 2026-11-27 in a Linux cloud container (provisional; the engine's tests are in huyz0/lucene-rust, at the revision this repo pins, `e6e974af`, checked out beside the other clone and built `--release`). Numbers below were read from those runs, not copied. The node-side tests were run with `cargo test -p oss-node --features coordinator,extensions` before the roadmap PRs of the same day.

Not every AC holds. The front end and its corpus are the engine's; the bounds that ADR 0069 puts on a script are mostly not built. The switch therefore stays off.

- AC-1: `cargo test -p lucene-painless --release --test front_parse` in lucene-rust: all 4,995 scripts Painless compiled parse (0 failures); of 1,620 Painless refused, 1,611 parse and 9 are refused at parse. `--test corpus` on the 4,964 sources: 15 refused with a reason (`unsupported painless construct: ...`), the rest run. NOT-RUN: that a refusal carries a source position (the test counts reasons, not offsets), and that every source Painless refused (status 2) is also refused by the analysis; only the parse step is counted.
- AC-2: `cargo test -p lucene-painless --release --test corpus`: 4,949 of 4,964 scripts match Painless's value or exception; the check passes 4,934 and 0 of those differ (`unsound = 0`). `--test front_lower`: 4,947 of 4,964 lower through the front end and match, 0 differ, 0 wrongly rejected; `--test front_sites`: 4,963 of 4,963 site tables equal Painless's, 0 differ. The unmatched: `DateTimeFormatter` fields and methods (6), `org.opensearch.painless.api.Debug` (3), `ZoneId.of`, `ZonedDateTime.parse`, `UUID.randomUUID`, regex flags 198, `MessageFormat.Field`, `Normalizer.Form`, a `Double[]` reference, one list shortcut. Through the node, a `script_score` equals the same expression: `painless_scores_like_the_same_expression`; a `doc` date, `_score` and `params` read as stock reads them is only partly shown here, by `a_script_reads_the_score_and_declares_variables` (docs/specs/painless-script-score/VERIFIED.md has the rest). NOT-RUN: a stock-OpenSearch comparison of a script through any site; the corpus has the language and not the contexts.
- AC-3: the floors are in the engine's tests and only go up: `MIN_PASS` 4,949, `MIN_CHECKED` 4,934, `MIN_LOWERED` 4,947, `MIN_EQUAL` 4,963 (`cargo test -p lucene-painless --release --test corpus --test front_lower --test front_sites`), each equal to what the run above measured.
- AC-4: partly met since the update below. Before it, NOT-RUN in the node. Built and tested in the engine: source over 65,535 bytes and parse depth over 100 are refused (the front end's bounds test, `cargo test -p lucene-painless --release --lib bounds_refuse_before_anything_runs`), and the per-function loop counter exists. Not built: the 20,000 IR node cap, the per-invocation memory arena (4 MiB, 1 MiB per string or collection), call depth 128 (the VM's cap is 200), the memory_per_invocation and max_loop_counter settings (neither is registered in this repo), and the compile cache. A script's script_exception for a bound past the two built ones is therefore not shown.
- AC-5: NOT-RUN: no test here refuses a script naming `ZonedDateTime`, `Optional`, a stream or `Class` with its offset, none refuses `Math.random` in a score context, and no recorded date-function table exists. Corpus scripts that name a date class are counted among the 15 refusals above.
- AC-6: `painless_is_served_only_while_the_switch_is_on` (crates/reader/src/dsl/queries/script_switch_tests.rs), `painless_source_is_refused_unless_its_variable_turns_the_compiler_on` (crates/node/src/boot/config/tests/switches.rs), and `what_is_not_served_is_refused` (crates/node/tests/it/function_score_script.rs) with the switch off.
- AC-7: `a_painless_script_adds_no_store_request` (crates/node/tests/script_score_painless.rs): the request counts of a Painless script_score equal the expression's. Stored script ids make one marker GET a TTL, held by `a_node_that_resolves_nothing_makes_no_request_and_a_ttl_makes_one_marker_get`.

Each site has its own VERIFIED.md, and each runs the same engine: `script_score`, `script_fields` and `_script` sort ([painless-script-score](../painless-script-score/VERIFIED.md), [script-fields](../script-fields/VERIFIED.md), [script-sort](../script-sort/VERIFIED.md)), the `script` query, the ingest `script` processor ([ingest-pipelines](../ingest-pipelines/VERIFIED.md)), `_update` ([node-update-route](../node-update-route/VERIFIED.md)), bulk update ([node-bulk-update](../node-bulk-update/VERIFIED.md)), `_update_by_query` ([node-update-by-query](../node-update-by-query/VERIFIED.md)), `_reindex` ([node-reindex](../node-reindex/VERIFIED.md)), `scripted_metric` ([scripted-metric](../scripted-metric/VERIFIED.md)), script and `moving_fn` pipeline aggregations ([pipeline-aggs-script](../pipeline-aggs-script/VERIFIED.md), [pipeline-aggs-moving-fn](../pipeline-aggs-moving-fn/VERIFIED.md)), and stored script ids ([stored-script-ids](../stored-script-ids/VERIFIED.md)).

## Not run

AC-4's bounds past source size and depth, AC-5 entirely, a stock-OpenSearch comparison of any site, the default flip. The `native_compile` default stays off.

## Update: limits and compile cache (2026-11-27)

AC-4 now has: the per-invocation allocation bound (4 MiB an invocation, 1 MiB a value) and the 20,000 IR node cap, held through the node by `a_script_past_its_limits_is_refused_and_the_node_goes_on` ([painless-limits](../painless-limits/VERIFIED.md)), and the compile cache bounded at 256 entries and 4 MiB reserved from the pool ([painless-compile-cache](../painless-compile-cache/VERIFIED.md)). Still not built: the call depth stays 200 (the spec says 128); the memory_per_invocation and max_loop_counter settings (the limits are constants); charging list and map growth and StringBuilder appends; the arena's counter against the allocator's peak asserted as AC-4 asks (a resident-memory check stands in). AC-5 is unchanged and NOT-RUN. The engine change is lucene-rust#616 (merged, pinned at `dbb34e98`).
