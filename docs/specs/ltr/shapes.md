# Response shapes of the stock LTR plugin, as written down here

From the plugin's published documentation examples; provisional until a stock run is recorded. A store create answers `{"acknowledged":true}`; a feature set or model put answers `{"_index":".ltrstore","_id":"<type>-<name>","_version":1,"result":"created","_shards":{"total":1,"successful":1,"failed":0},"_seq_no":0,"_primary_term":1}`; a get answers `{"_index":".ltrstore","_id":"<type>-<name>","_version":1,"found":true,"_source":{"name":"<name>","type":"featureset|model","<type>":{...}}}`; a missing one `{"_index":".ltrstore","_id":"<type>-<name>","found":false}` with 404; a delete answers `{"_index":".ltrstore","_id":"<type>-<name>","_version":2,"result":"deleted",...}`. The `_index` is the store's name in the plugin's convention (`.ltrstore` for the default, `.ltrstore_<store>` otherwise); a Rust node reports that name though it keeps blobs.
